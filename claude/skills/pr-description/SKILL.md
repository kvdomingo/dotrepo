# PR Description

## Step 0: Select the correct `gh` account

Pick the account from the current working directory before any `gh` call:

- **Eyva account** `eyva-kenneth-domingo` — if the resolved absolute CWD is anywhere under `~/eyva` (any depth).
- **Default account** `kvdomingo` — for everything else.

```bash
gh auth switch --user <account-name>
```

Verify the switch succeeded. If it fails, halt and report — never proceed on the wrong account.

## Step 1: Detect the base branch (MANDATORY — do this first, always)

Never assume `main`. Detect the real base branch before diffing or writing anything.

**If the PR already exists on GitHub:**
```bash
gh pr view --json baseRefName -q '.baseRefName'
```

**If the PR does not exist yet, check the remote default and available dev branches:**
```bash
# Check what the remote HEAD points to
git remote show origin | grep 'HEAD branch' | awk '{print $NF}'

# List remote branches to identify common dev branch names
git branch -r | grep -E 'origin/(dev|development|staging|main|master)$'
```

Use the result of these commands as `BASE_BRANCH`. Do not hardcode `main`.

## Step 2: Check for a PR template

Look for a PR template in the repo (in order of precedence):

```bash
find . -maxdepth 3 -type f \( \
  -path './.github/PULL_REQUEST_TEMPLATE.md' \
  -o -path './.github/PULL_REQUEST_TEMPLATE/*.md' \
  -o -path './docs/pull_request_template.md' \
  -o -name 'pull_request_template.md' \
\) 2>/dev/null | head -5
```

If a template is found, read it and use it as the body structure. If none is found, use the default template in Step 3.

## Step 3: Gather diff and commit history

Run these in parallel once `BASE_BRANCH` is confirmed:

```bash
git log origin/BASE_BRANCH..HEAD --oneline
git diff origin/BASE_BRANCH...HEAD
git branch --show-current
```

## Step 3: Create or update the PR

**Create a new PR:**
```bash
gh pr create --base BASE_BRANCH --assignee eyva-kenneth-domingo --title "..." --body "$(cat <<'EOF'
## Summary
- <bullet>

## Test plan
- [ ] <step>

🤖 Generated with [Claude Code](https://claude.com/claude-code)
EOF
)"
```

**Update an existing PR:**

First read the current body so existing content is preserved:
```bash
gh pr view --json body -q '.body'
```

When rewriting, **preserve verbatim** any blocks authored by other AI agents or bots (e.g. sections marked `<!-- AI-generated -->`, bot checklists, automated tool output) and any human-written content that is still relevant. Reuse the existing section structure rather than reorganizing it.

```bash
gh pr edit --body "$(cat <<'EOF'
## Summary
- <bullet>

## Test plan
- [ ] <step>

🤖 Generated with [Claude Code](https://claude.com/claude-code)
EOF
)"
```

## Rules

- Select the correct `gh` account (Step 0) before any `gh` call, and never proceed on the wrong account.
- The `--base` flag must always reflect the detected base branch, not `main`.
- When updating an existing PR, never delete or modify blocks generated by other automated tools/AI agents — preserve them verbatim.
- Always assign newly created PRs to `eyva-kenneth-domingo` via `--assignee` (the repo owner). If the PR already exists, add the assignee with `gh pr edit --add-assignee eyva-kenneth-domingo`.
- PR title: under 70 characters, imperative voice, describes what the branch does.
- Summary: 1–3 bullets on *what* changed and *why* — not a list of every file.
- Test plan: actionable checklist of steps to verify the change works correctly.
